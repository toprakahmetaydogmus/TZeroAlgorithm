# T-Zero v12.3.1 — Cloud Fallback Removal, Full Privacy Transparency & Clean Registry Release

## Highlights
- **Removed Remaining Implicit Cloud Fallbacks (Issue #47):** `ContextExportManager.generate_architecture_blueprint` and desktop generator `AutoReadmeGUI.async_generate_payload` no longer silently fall back to Pollinations (`https://text.pollinations.ai/`) when API keys are missing or a configured provider errors — missing credentials or remote provider errors now fall back strictly locally to deterministic AST generation (`generate_offline_architecture_blueprint` / `generate_offline_context`).
- **Complete Privacy & Network Disclosure (`PRIVACY.md` + Docs):** Updated `PRIVACY.md`, `README.md`, `AI_INSPECTION.md`, `llms.txt`, `benchmark-site/`, and `docs/README.*.md` so every local vs. optional-network boundary (AI providers, DuckDuckGo search, GitHub/PyPI/npm metadata, `tzero --add-to-path`, optional Anti-REA webhook) is documented clearly without blanket `"100% offline"` claims.
- **180-Tier Metadata Consistency:** Updated package description (`pyproject.toml`), VS Code extension strings, CLI/TUI/GUI labels from legacy `26-Tier` to `180-Tier Anti-REA`.
- **Regression Test Coverage:** Added `tests/test_network_disclosure.py` verifying zero unrequested outbound calls when API credentials are absent or fail, and ensuring clean `tzero-mcp@12.3.1` publication across PyPI, npm, Open VSX, GitHub Releases, Winget, Scoop, Vercel, and Hugging Face.
