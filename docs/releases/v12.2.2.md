## Highlights

### 1. Full Security Audit Hardening (Findings 01–14)
- **PEM Private Keys (01):** Multi-line `-----BEGIN ... PRIVATE KEY-----` to `-----END ... PRIVATE KEY-----` blocks are redacted as a single unit; incomplete PEM blocks abort sanitization (`ValueError`) rather than leaking inner base64 key lines.
- **AST + Text Sanitization Parity (02):** `ZeroLeakEngine.sanitize_ast` strips secrets directly from `ast.Constant` nodes (even unquoted tokens) and runs a final verification scan on unparsed output.
- **Atomic Cross-File Auto-Vault (03, 04, 05, 06):**
  - Resolves target project root from `.git` ancestor instead of current working directory.
  - Preserves LHS variable names and assignments (`api_key = os.environ.get("...", "")`).
  - Uses a shared symbol table across files and existing `.env` definitions so distinct keys never collide (`OPENAI_API_KEY`, `OPENAI_API_KEY_2`, ...) and repeat runs remain idempotent.
  - Verifies `.gitignore` via real `git check-ignore` / `ls-files --error-unmatch` (warning if `.env` is already tracked) and stages all writes atomically, rolling back cleanly if `.env` or `.gitignore` writes fail.
- **Non-Destructive Anti-REA Directory Output (07):** `protect_path_with_armor(dir, output_path=out_dir)` mirrors protected files into `out_dir` without mutating original source files and tracks per-file failures accurately.
- **Full Raw Unpruned MCP Security Scan (08):** `verify_security_guard` / `verify_zero_leak_security` scans complete raw workspace files before AST pruning and separately tracks `fully_scanned`, `partially_scanned`, `skipped`, and `unreadable` counts.
- **Safe Chained Git Hooks & Fail-Closed Scans (09, 10):** `GitSecurityGuard.install_hook` backs up and chains pre-existing custom Unix/Windows `pre-commit` hooks cleanly (`uninstall_hook` restores them); `run_cli_check` fails closed on `git diff`/`git show` errors and scans comments cleanly.
- **Symlink/Junction & TOCTOU Safe MCP Resource (11):** `tzero://file/{path}/skeleton` validates `os.path.realpath` containment plus open descriptor `(st_dev, st_ino)` identity verification.
- **Strict Legacy Backup Validation (12):** `KeyringSecretsBackupManager` separates legacy XOR import schema checks and rejects malformed payloads before touching the OS keyring.
- **Bounded Local Context Proxy (13):** `ContextProxyHandler` enforces a 2 MiB max `Content-Length`, 10s socket read timeout, and bounded multi-threaded concurrency semaphore.
- **VS Code Sidebar Command Allowlist & Strict Nonce CSP (14):** `dispatchSidebarMessage` restricts sidebar Webview dispatch strictly to `ALLOWED_SIDEBAR_COMMANDS` and removes `'unsafe-inline'` via cryptographic CSP nonces.

### 2. Anti-REA Correctness, Integrity & Packaging
- Preserves `# -*- coding: utf-8 -*-`, module docstrings, and `from __future__ import ...` ordering at the top of transformed Python files, plus `compile(...)` verification in staging before overwriting targets.
- Fixes `StringVault` UTF-8 multi-byte decoding (e.g. Turkish characters round-trip losslessly).
- Updates `MemoryIntegrityGuard` to verify real `co_code` SHA-256 digests and fixes `AIResistanceAuditor` identifier-only homoglyph inspection + explicit static indicator labeling.
- Returns non-zero exit codes on missing/unreadable CLI audit targets and includes `NOTICE` in both the Windows release ZIP and VS Code extension package.
- **Optional Webhook Telemetry Disclosure:** If a user explicitly supplies `webhook_canary` to `AntiREAEngine.protect_python_source`, `CanaryBeacon` dispatches async alert JSON containing `threat_type`, `detected_tool`, `timestamp`, `platform`, `os_name`, `python_version`, `pid`, and truncated `hostname[:16]`. Disabled by default when no webhook is configured.
